# 学习日志：让理解有证据

从项目的问题出发，按 **Prediction → Experiment → Evidence → Conclusion** 记录一次真实学习过程。公开资料来自 [节点 Mapping](../references/course_mapping.md)，个人先学什么仍由 [roadmap](../roadmap.md) 决定。

## 新建一条记录

复制 [日志模板](_template.md) 到 `YYYY/YYYY-MM-DD_Kxx_problem.md`，例如 `2026/2026-10-xx_K02_spi-registers.md`（仅命名示例）。一次过程关联多个节点或课号时只写一次，目录不按学校/lecture 序列扩张。实际发生学习后才建记录；本次未预建 lecture 日志或代填个人理解。

运行前先填写预测：哪些信号在哪一沿变化？期望哪个故障被检测？综合会增加何种寄存器或负载？随后写实际观察，保留失败和假设修订。手算也是证据，但验证层次必须注明；未运行的工具实验写“未运行”。

## 实际记录索引

目前没有登记个人公开课学习日志。新增实际记录时，在这里按主要节点添加一行：日期、节点/问题、日志链接、资源 ID、课号/实验 ID、本人学习状态、实验状态/层次。

来源核对、本人学习、工程实验三类状态分开。例如来源公开可读不意味着已阅读；已有 SPI PASS 不意味着本人已解释寄存器更新。下一步建议从 K02 的同沿更新预测开始，再对照第 01 课与已有 SPI 波形。
